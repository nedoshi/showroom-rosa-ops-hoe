== Introduction

Deploy the standard Istio *Bookinfo* sample into the mesh, add DestinationRules for version subsets, and expose the app with the *Kubernetes Gateway API*.

Service Mesh 3 does not deploy an ingress gateway as part of the `Istio` CR.
On OpenShift 4.19+, Gateway API CRDs are platform-managed; Istio provides the `istio` GatewayClass after the control plane is Healthy.

Sample manifests are pinned to the OpenShift Service Mesh Istio `release-1.28` branch, which matches the Istio control plane version validated with Service Mesh Operator 3.3.x on this workshop path.

:numbered:
== Create and enroll the Bookinfo project

. Create the project:
+
[source,sh,role=execute]
----
oc new-project bookinfo
----

. Label the namespace for discovery *and* sidecar injection.
Both labels are required when using discovery selectors on the `Istio` CR (as configured in the previous lab):
+
[source,sh,role=execute]
----
oc label namespace bookinfo istio-discovery=enabled istio-injection=enabled --overwrite
----
+
[NOTE]
====
If your `Istio` resource name is not `default`, use `istio.io/rev=<IstioRevisionName>` instead of `istio-injection=enabled`.
====

=== Deploy Bookinfo workloads

. Apply the Bookinfo manifests:
+
[source,sh,role=execute]
----
oc -n bookinfo apply -f \
  https://raw.githubusercontent.com/openshift-service-mesh/istio/release-1.28/samples/bookinfo/platform/kube/bookinfo.yaml
----
+
.Sample Output
[source,text,options=nowrap]
----
service/details created
serviceaccount/bookinfo-details created
deployment.apps/details-v1 created
service/ratings created
serviceaccount/bookinfo-ratings created
deployment.apps/ratings-v1 created
service/reviews created
serviceaccount/bookinfo-reviews created
deployment.apps/reviews-v1 created
deployment.apps/reviews-v2 created
deployment.apps/reviews-v3 created
service/productpage created
serviceaccount/bookinfo-productpage created
deployment.apps/productpage-v1 created
----
+
Source on GitHub: https://github.com/openshift-service-mesh/istio/blob/release-1.28/samples/bookinfo/platform/kube/bookinfo.yaml[bookinfo.yaml].

. Apply DestinationRules so version subsets (`v1`/`v2`/`v3`) exist for traffic shifting:
+
[source,sh,role=execute]
----
oc -n bookinfo apply -f \
  https://raw.githubusercontent.com/openshift-service-mesh/istio/release-1.28/samples/bookinfo/networking/destination-rule-all.yaml
----
+
.Sample Output
[source,text,options=nowrap]
----
destinationrule.networking.istio.io/productpage created
destinationrule.networking.istio.io/reviews created
destinationrule.networking.istio.io/ratings created
destinationrule.networking.istio.io/details created
----

. Create the Gateway API `Gateway` + `HTTPRoute`:
+
[source,sh,role=execute]
----
oc -n bookinfo apply -f \
  https://raw.githubusercontent.com/openshift-service-mesh/istio/release-1.28/samples/bookinfo/gateway-api/bookinfo-gateway.yaml
----
+
.Sample Output
[source,text,options=nowrap]
----
gateway.gateway.networking.k8s.io/bookinfo-gateway created
httproute.gateway.networking.k8s.io/bookinfo created
----

== Verify the Bookinfo installation

. Wait for application pods. Sidecar injection succeeded when each Bookinfo workload shows `2/2` Ready:
+
[source,sh,role=execute]
----
oc -n bookinfo get pods
----
+
.Sample Output
[source,text,options=nowrap]
----
NAME                                      READY   STATUS    RESTARTS   AGE
bookinfo-gateway-istio-xxxxxxxxxx-xxxxx   1/1     Running   0          30s
details-v1-xxxxxxxxxx-xxxxx               2/2     Running   0          40s
productpage-v1-xxxxxxxxxx-xxxxx           2/2     Running   0          40s
ratings-v1-xxxxxxxxxx-xxxxx               2/2     Running   0          40s
reviews-v1-xxxxxxxxxx-xxxxx               2/2     Running   0          40s
reviews-v2-xxxxxxxxxx-xxxxx               2/2     Running   0          40s
reviews-v3-xxxxxxxxxx-xxxxx               2/2     Running   0          40s
----

. Confirm the Gateway is programmed and has an address:
+
[source,sh,role=execute]
----
oc -n bookinfo wait --for=condition=programmed gtw/bookinfo-gateway --timeout=180s
oc -n bookinfo get gtw bookinfo-gateway
----

. Build the product page URL from the Gateway address:
+
[source,sh,role=execute]
----
echo "http://$(oc -n bookinfo get gtw bookinfo-gateway -o jsonpath='{.status.addresses[0].value}')/productpage"
----
+
[WARNING]
====
This is an `http` URL. Some browsers upgrade to `https` and fail.
On ROSA the address is typically an AWS load balancer hostname — allow a minute for DNS before testing externally.
====

. Verify in-cluster that Bookinfo is serving:
+
[source,sh,role=execute]
----
oc -n bookinfo exec "$(oc get pod -l app=ratings -n bookinfo -o jsonpath='{.items[0].metadata.name}')" \
  -c ratings -- curl -sS productpage:9080/productpage | grep -o '<title>.*</title>'
----
+
.Sample Output
[source,text,options=nowrap]
----
<title>Simple Bookstore App</title>
----

. Open the product page URL from the Gateway step in a browser.
You should see *"The Comedy of Errors"*. If reviews show an error, wait a few seconds and refresh.

*Congratulations!*

Bookinfo is running in the Service Mesh 3 data plane and is reachable through the Gateway API ingress.
